# Sinawi 운영 규칙 (앱이 강제하는 것)

근거는 [RESEARCH.md](./RESEARCH.md). 코드: `server/supervision.ts`, `server/orchestra.ts`.

## R1. 위임 브리프 (강제 + 자동 보완)
총괄 프롬프트에 6개 제목 규칙을 넣는다: **목표 / 맥락 / 완료 기준 / 제약 / 검증 / 보고 형식**.
위임 본문에서 빠진 제목은 앱이 기본값으로 채워 작업자에게 보낸다(`ensureBrief`). 맥락이 없으면 사용자 원래 요청을 붙인다. 제약 기본값에는 다른 작업자의 변경을 되돌리지 말 것과, 가장 가까운 AGENTS.md, CLAUDE.md, GEMINI.md를 따를 것을 넣는다.
보완된 칸은 위임 이벤트 `metadata.briefAutofilled`에 남는다.

## R2. 작업자 운영 규칙 (모든 작업자 프롬프트 앞)
- 편집 전에 대상 파일을 읽는다. 이전 결과에 의존하는 단계는 결과를 확인한 뒤에만 진행한다.
- 같은 오류 3번, 또는 같은 수정 3번 실패면 같은 방법 중단 → 원래 목표·시도·오류·의심되는 가정을 '막힘'으로 보고.
- 추측 금지: 관찰(파일·출력·snapshot) 후 행동. 라이브러리·명령은 설정 파일에서 확인한다.
- TODO나 주석으로 구현을 대신하지 않는다. 요청한 범위만 완전히 구현한다.
- 다른 작업자나 사용자의 변경은 되돌리지 않는다.
- 수정하는 파일을 포함하는 가장 가까운 AGENTS.md, CLAUDE.md, GEMINI.md를 따른다. 브리프와 사용자 지시가 그 파일보다 우선한다.
- 끝났다고 하기 전에 직접 검증하고 증거를 남긴다. 못 했으면 '부분 완료'. 보고 끝에 질문이나 추가 제안을 붙이지 않는다.
- 보고 형식: 상태 / 한 일 / 증거 / 남은 문제.

## R3. 정체 감지 → 작업자 중단
작업자 실행마다 `StallDetector`가 붙는다.
- **같은 오류 3회**(최근 15개 도구 이벤트 안, 선택자·숫자·경로가 달라도 같은 메시지면 같은 오류)
- **같은 명령 4회**
- **5분 동안 의미 있는 이벤트 없음**(노이즈 제외)
걸리면 "정체 감지" 경고를 남기고 **그 작업자 CLI만** 멈춘다(세션은 계속). 세션 전체 10분 무이벤트 타임아웃은 그대로 둔다.

## R4. 검증 단계 + 재계획
모든 워커 보고가 "상태: 완료"로 시작하면 검증 없이 그 보고가 최종 답이 된다(Claude Code·Codex처럼 하위 작업 결과를 다시 돌리지 않는다). "부분 완료"·"막힘"·정체·중단이 있을 때만 총괄이 읽기 전용 검증을 받는다.
- 검증 실행에는 원래 사용자 요청과 앱이 실행한 git 상태(`status`, 최근 커밋, 원격 기본 브랜치)가 들어간다. Grok 검증에는 셸과 MCP가 없다.
- 검증이 CLI 쪽에서 끊기면 조용히 "완료"로 끝내지 않고, 경고와 함께 워커 보고를 그대로 보여 준다.
- 각 보고를 완료 기준과 하나씩 대조한다. 증거 없는 "완료"는 미확인. 워커가 적은 증거를 그대로 믿지 않고, 가능하면 파일이나 테스트 결과로 다시 본다.
- 보고할 문제: 테스트·타입 실패, 입력과 상관없이 틀리는 로직, 브리프 제약 위반, 범위 밖 변경. 스타일 취향과 원래부터 있던 문제는 뺀다.
- 정체·중단·기준 미달이면 (a) 원래 목표를 다시 적고, (b) 틀렸을 수 있는 가정을 나열하고, (c) **다른 접근**으로 재위임(최대 2회, 6개 제목). 기회가 끝나면 위임 금지, 확인된 것/안 된 것을 구분해 답한다.

## R5. 승인 게이트
되돌릴 수 없는 작업(커밋·push·배포·삭제·결제·외부 전송)은 사용자가 명시하지 않으면 위임하지 않고 사용자 확인을 받는다. 위험 우회 플래그(always-approve, dangerously-bypass)는 쓰지 않는다.

## R6. 도구 출력 노이즈
- CLI 자식 환경에서 `NO_COLOR`와 `FORCE_COLOR`를 둘 다 제거(`cliChildEnv`) → Node 경고 원인 제거.
- 그래도 들어온 경고 줄은 이벤트·정체 판단에서 제거(`stripToolNoise`).

## R7. 브라우저 규율 (ao-browser)
goto 뒤 **snapshot 먼저**, 반환된 ref(e12)로 조작. 선택자 짐작 연타 금지. "요소를 찾을 수 없습니다"면 snapshot부터 다시. 결과물·목업·디자인 시안은 앱 브라우저로만 연다. 외부 Chrome, Playwright, `open`은 쓰지 않는다. 명령 전문은 [prompts/in-app-browser.md](./prompts/in-app-browser.md). 프롬프트에는 `BROWSER_CORE`만 넣는다.

## R8. 실행 중 대화
실행 중 입력은 막지 않는다. 상태 질문은 로그 기반 읽기 전용 답, 방향 지시는 다음 턴 대기열, "멈춰"는 즉시 중지(live-turn).

## R9. 라우팅 기본값
- 총괄: Claude → Codex → Grok (한도·정책에 따라 자동 대체).
- 구현·버그·테스트: Codex 우선. 설계·문서·리뷰: Claude. 미디어·빠른 조사·상태 답변: Grok.
- 회사 공간 Codex 금지, bbanana는 Claude 금지 (기존 정책 유지).
- 같은 파일을 두 작업자에게 동시에 맡기지 않는다.

## R10. 이 앱에서 일하기
총괄·워커 프롬프트 끝에 `APP_GUIDE`를 붙인다. 전문은 [prompts/app-guide.md](./prompts/app-guide.md). 한국어로 짧게 답하고, 결과는 세션 작업 폴더의 마크다운 경로로 남겨 앱 뷰어가 열게 한다. 사용자가 보낸 `orchestra-attachments`의 selector는 ao-browser ref가 아니다. 사용자가 이미 띄워 둔 서버의 포트와 사용자가 명시하지 않은 프로세스 kill은 금지한다. 6필드 브리프, 정체 감지, 재위임, CLI별 지침은 그대로다.

## 조정값
`Orchestra.stallOptions = { repeatLimit, window, idleMs }`, 재계획 상한 `maxReplanRounds = 2`.

## 프롬프트 품질 (2026-10-31, 공개 코딩 에이전트 조사 반영)
코드가 강제하는 것은 위 6필드 자동 보완, 정체 감지, 재위임 상한, Grok 실패 시 재위임 재요청이다. 아래는 프롬프트로 넣는 품질 규칙이다. 근거는 [PROMPTS-STUDY.md](./PROMPTS-STUDY.md).
- 총괄은 계획·위임·검증·보고만 한다. 워커가 일하는 동안 같은 일을 직접 하지 않는다.
- 계획은 2단계 이상일 때만. 한 단계 계획은 만들지 않는다. 출력이 큰 테스트는 워커가 요약만 돌려준다.
- CLI별 보정(`cliNotes`)을 총괄·워커 프롬프트 뒤에 붙인다. 한도 전환으로 CLI가 바뀌면 `retargetCliNotes`가 그 문구를 갈아 끼운다. Codex는 `update_plan`, `apply_patch`, AGENTS.md, 짧은 보고. Claude는 CLAUDE.md, TodoWrite, 서브에이전트 금지, 근거 있는 리뷰. Grok은 허용된 명령 하나씩과 거부 시 즉시 보고 후 재위임.
- 계획 전문 에이전트가 있으면 읽기 전용으로 확인 가능한 단계, 가정, 완료 조건만 쓴다.
