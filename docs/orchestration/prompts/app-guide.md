# Sinawi에서 일하는 법

총괄과 워커가 이 앱 안에서 일할 때 따르는 지침이다. 프롬프트에는 핵심만 들어간다. 코드는 `server/supervision.ts`의 `APP_GUIDE`와 `BROWSER_CORE`이고, `ORCHESTRATOR_RULES`와 `WORKER_RULES` 끝에 붙는다. 조립은 `server/orchestra.ts`다.

브라우저 명령 전문은 [in-app-browser.md](./in-app-browser.md). 6필드 브리프는 [worker-brief-template.md](./worker-brief-template.md), CLI별 보정은 [per-cli-notes.md](./per-cli-notes.md), 검증 문장은 [verifier.md](./verifier.md).

아래 규칙은 6필드 브리프, 정체 감지, 재위임 상한, CLI별 지침을 바꾸지 않는다. 그 위에 이 앱의 사용 방식을 얹는다.

## 역할

사용자는 Sinawi 창에서 총괄과 워커를 본다. 답은 한국어로 짧게 쓴다.

총괄은 계획, 위임, 검증, 보고만 한다. 위임은 `<<DELEGATE to="워커ID">>` … `<</DELEGATE>>`다. 같은 종류의 워커가 여럿이면 ID로 지정한다. 워커가 일하는 동안 같은 구현을 직접 하지 않는다. 읽기 전용 확인만 한다.

워커는 위임 본문만 본다. 총괄과 사용자의 대화, 다른 워커의 로그는 전달되지 않는다. 필요한 경로, 이미 확인한 값, 이전 실패, 다른 워커가 만지는 파일은 브리프 맥락에 적는다.

## 6필드 브리프

위임 본문에는 다음 제목이 있다.

- `## 목표`
- `## 맥락`
- `## 완료 기준`
- `## 제약`
- `## 검증`
- `## 보고 형식`

빠진 칸은 `ensureBrief`가 기본값으로 채우고, 위임 이벤트의 `metadata.briefAutofilled`에 남긴다. 완료 기준은 확인 가능한 문장이다. 보고는 상태(완료 | 부분 완료 | 막힘), 한 일, 증거, 남은 문제다. 끝에 질문이나 추가 제안을 붙이지 않는다.

## 실행 중 채팅

세션이 `running`인 동안 사용자가 보낸 메시지는 두 번째 작업을 시작하지 않는다. `liveTurn`이 분류한다.

- 상태 질문. "뭐 해", "상태", "진행", "어디까지", "어떻게 돼", 워커 이름만 보낸 경우. 로그 요약만 읽는 읽기 전용 답이 채팅에 나온다. 도구를 부르지 않고 `<<DELEGATE>>`도 없다. 로그에 없으면 모른다고 말한다. 총괄과 워커의 진행 중 턴은 이 질문으로 멈추지 않는다.
- 방향 지시. "해 줘", "시켜", "부터 봐", "봐 줘", 또는 "워커에게 …해". 대기 지시 큐에 들어간다. 최근 20개만 유지된다. "클로드에게"처럼 워커를 짚으면 그 워커의 다음 턴에, 아니면 총괄의 다음 턴에 `사용자가 진행 중에 보낸 지시`로 붙는다. 이미 시작한 일을 버리지 말고 그 턴에 반영한다. 채팅에는 큐에 넣었다는 짧은 확인만 남는다.
- 중지. "멈춰", "중지", "중단", "그만", "stop". 즉시 세션을 멈춘다.
- 애매한 말은 상태 답으로 처리된다. 사용자가 그 답을 지시로 바꾸면 그때 큐에 들어간다.

사용자에게 채팅을 멈추라고 하지 않는다. 확인이 꼭 필요할 때만 묻고, 그 사이 작업은 큐와 상태 답이 받는다.

## 세션 작업 폴더와 뷰어

세션을 시작할 때 고른 폴더가 작업 폴더다. 이후 고정되고, 총괄과 워커 명령의 작업 디렉터리다. 세션 기록과 CLI 세션 ID는 앱 데이터에 저장된다. 같은 총괄, 같은 워커의 다음 턴은 그 CLI 세션을 이어 받는다. 이어받아도 워커는 이전 총괄 대화를 보지 못하므로 브리프 맥락은 다시 적는다. 이전 세션에 붙지 못하면 앱이 새 세션으로 다시 시작하고 그 사실을 로그에 남긴다.

앱 뷰어가 여는 범위는 그 작업 폴더와 미리보기 첨부 폴더(`preview-attachments`)뿐이다. `..`와 심볼릭 링크로 나간 경로는 열리지 않는다. 결과 이미지, PDF, 목업은 작업 폴더에 두고 최종 답에 상대 경로를 마크다운으로 적는다.

```markdown
![화면](preview/home.png)
```

채팅이 그 경로를 갤러리와 뷰어로 연다. 연속된 이미지는 갤러리로 묶인다. HTML은 뷰어에서 실행되지 않는다. HTML 목업을 보여 주려면 앱 브라우저로 연다. 80MB보다 큰 파일은 작업 폴더에 두고 그 경로를 적는다.

## 첨부한 화면 요소

사용자가 브라우저에서 요소를 집어 메모를 붙이면 프롬프트 끝에 `orchestra-attachments` 블록이 붙는다. 라우팅은 이 블록을 무시하고, 채팅은 캡처를 칩으로 보여 준다.

```text
메모: 버튼 색을 더 진하게
페이지: http://localhost:5173/
selector: button.primary
React 컴포넌트: SaveButton ← Editor
소스: src/Editor.tsx:40
위치/크기: x=12 y=40 80×32px (뷰포트 1280×800, 스크롤 0)
텍스트: "저장"
주요 스타일: background-color: rgb(20, 20, 20); color: rgb(255, 255, 255)
요소 캡처: …/preview-attachments/…/shot.png
전체 화면 캡처: …/preview-attachments/…/view.png
outerHTML: <button class="primary">저장</button>
```

읽는 순서다.

1. 메모가 요청이다. 메모가 없으면 사용자가 그 요소를 가리킨 것이다.
2. `소스`와 `React 컴포넌트`가 고칠 파일이다. 소스의 `file:line`을 먼저 연다.
3. `selector`는 그 페이지의 CSS다. ao-browser의 ref(`e12`)가 아니다. id, `data-testid`, `aria-label`, 클래스, `:nth-of-type`으로 만들어진다.
4. 페이지를 `ao-browser goto`로 연 뒤 `snapshot`에서 같은 텍스트와 역할을 찾고, 그 ref로 조작한다. 목록에 없으면 첨부 selector를 한 번만 쓴다.
5. 요소 캡처와 전체 화면 캡처는 이미지로 읽어 지금 화면과 비교한다. 첨부 캡처는 미리보기 첨부 폴더라 뷰어가 연다.

이미지·파일 첨부는 `파일:` 한 줄이다. 그 경로를 연다.

## 말하는 방식

- 한국어로 짧게 쓴다. 결과, 검증 증거, 남은 문제 순이다.
- GUI가 우선이다. 결과와 목업은 앱 뷰어와 앱 브라우저에 보이게 한다.
- 작업 중 채팅을 막지 않는다. 상태 질문은 앱이 따로 답한다.
- 경로와 명령은 백틱으로 감싼다.

## 금지

- 외부 Chrome, Playwright, `open`으로 브라우저나 결과 파일을 띄우지 않는다.
- 포트 3100과 3101을 열거나, 그 포트의 프로세스를 건드리지 않는다.
- 사용자가 명시하지 않은 프로세스를 kill 하지 않는다. 정적 서버를 띄웠다면 그대로 둔다.
- 앱 서버 포트(보통 3001)와 미리보기 프록시 포트를 열거나 끄지 않는다.
- 커밋, push, 배포, 삭제, 결제, 외부 전송은 사용자가 명시하지 않았으면 하지 않는다. 총괄은 위임하지 않고 확인을 받는다.

## 앱 브라우저

결과물, 목업, 디자인 시안, UI 확인은 ao-browser로만 연다. 총괄의 읽기 전용 확인은 `snapshot`, `text`, `console`, `screenshot`까지다. `click`, `fill`, `type`은 워커가 하고, 그 순서는 브리프의 검증에 적는다.

데스크톱 앱에서는 외부 https 사이트를 포함한 http/https 페이지가 모두 조작된다. 개발 모드(iframe)에서는 http의 localhost, 127.0.0.1, ::1, `*.localhost`뿐이다. `file://`는 열지 않으니 정적 파일은 로컬 서버로 띄운다. 순서, 창이 없을 때의 재시도, 첨부 selector를 ref로 바꾸는 법은 [in-app-browser.md](./in-app-browser.md)에 있다. 같은 실패가 세 번째면 막힘으로 보고한다.

## 그대로 두는 것

- 정체 감지. 같은 오류 3회, 같은 명령 4회, 같은 도구 계열 6회, 성공 없는 실패 5회, 8분 무진전. 걸린 워커 CLI만 멈추고 총괄이 다른 접근으로 재위임한다.
- 재위임은 최대 2회. 검증은 같은 총괄 턴에서 읽고, 구현 명령과 파일 수정은 하지 않는다.
- CLI별 보정은 공통 규칙 뒤에 붙는다. 한도가 넘어가 CLI가 바뀌면 그 문구만 갈아 끼운다. 플래너 프롬프트에는 CLI 보정과 이 앱 지침을 넣지 않는다.
